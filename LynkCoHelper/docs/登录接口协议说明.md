# 领克 App 登录接口协议说明

本文档记录 `lynkco_login.py` 涉及的登录相关接口协议细节，从真机抓包逐字段验证得到，供后续维护参考。

## refreshToken 自动续期

```
GET https://app-services.lynkco.com.cn/auth/login/refresh?deviceId=<deviceId>&refreshToken=<refreshToken>
```

该网关支持两种独立的客户端认证方式，`refresh_token()` 按优先级依次尝试：

- **方案一：AppCode 静态认证**（`refresh_token_by_appcode`）—— 仅需固定的 `Authorization: APPCODE <code>` 请求头，无需签名运算。
- **方案二：AppKey/AppSecret HMAC 签名认证**（`refresh_token_by_signature`）—— 需要 `build_native_signature` 生成的动态签名头。

两者返回结构一致，若方案一失败自动回退到方案二。

## 账号密码/短信验证码登录全流程

从零开始登录（无 refreshToken、无历史 token 时）涉及极验（Geetest v4）滑块验证码，人机挑战部分需人工完成。完整链路：

1. `GET /auth/v1/security/config?type=GEE_TEST_V4`
   返回 `{"apiServer","staticServer","resourcePath","captchaId"}`，用于渲染极验 GT4 滑块。这几个字段实测固定不变（`apiServer`/`staticServer` 固定为 `https://captcha4.geely.com`）。

2. 用户在极验滑块完成人机验证（GT4 Web SDK 标准流程），得到 `lot_number` / `captcha_output` / `pass_token` / `gen_time` 四个字段。

3. `POST /auth/v1/security/geeTestV4/validate`
   Body: `{"passToken","lotNumber","genTime","captchaOutput","scene"}`。
   `scene` 区分业务场景：密码登录传 `"passwordLogin"`，短信验证码登录传 `"mobileLoginSendsms"`。
   响应 `data.certifyId` 实测直接等于请求里的 `lotNumber`。

4. `POST /auth/login/sliding/sendSms`
   Body: `{"mobile","challenge"}`，`challenge` 即上一步的 `certifyId`（=`lotNumber`）。

5. `POST /auth/login/mobileCodeLogin?deviceType=ANDROID&appVersion=<ver>&hardwareDeviceId=<deviceId>&mobile=<手机号>&deviceModel=<型号>&verificationCode=<短信验证码>`
   全部参数走 query string，而非 JSON body；body 固定为空 JSON 对象 `"{}"`（仍需计算 Content-MD5 参与签名）。返回 `centerTokenDto`（`token`/`refreshToken`/`expireAt` 等）。

另有一条"账号密码 + 免验证码"登录路径 `login_by_password()`（对应 `POST /auth/login/sliding/login`），在陌生设备上会被风控拦截返回 `{"code":"untrusted.device",...}`，需回退到上面第 4/5 步的短信验证码流程；密码字段加密算法未逆向确认，不建议依赖。

以上接口除 `x-ca-key`/`nonce`/`timestamp` 外，还需携带 `x-ca-appcode: SWGeelyCode`（仅 `config`/`geeTestV4/validate` 两个接口），均走 `build_native_signature` 原生签名体系，POST 请求需要真实计算 Content-MD5 参与签名（即使 body 是空对象 `"{}"` 也要计算）。
