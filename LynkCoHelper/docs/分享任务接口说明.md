# 领克 App 分享任务接口说明

分享一篇文章可以给账号增加能量体奖励，从真机抓包验证得知完整流程横跨"原生签名"和"H5签名"两套认证体系（`lynkco_common.py` 中均已实现），供 `lynkco_share.py` 参考。

## 简化两步法（推荐，`do_share()` 默认使用）

1. App 原生端调用 `GET /app/v1/task/getShareCode`（走原生 `NATIVE_APP_KEY` 签名，需携带 `risk_request_info` 等风控头，其中 `shareContentURL` 带着被分享文章的 id），拿到本次分享的 `shareCode`。
2. H5 端调用 `POST /app/v1/task/shareReporting?shareCode=<shareCode>`（H5 签名，`Origin` 需为 `https://h5.lynkco.com`，注意与签到接口的 `h5.lynkco.cn` 不同域名），body 必须带上 `{"businessNo": "<文章id>", "eventData": {...}}`。网关会校验两步的文章 id 一致，这是真正加分的必要条件。

## 完整三步法（兜底，`content_id` + 另一账号点击分享链接的场景）

依次调用 `shareCodeToUserId`（反查分享人）-> `shareContentContectCheck`（前置校验）-> `shareContentContectReporting`（真正上报加分）。

## 重要限制：接口返回成功不代表真正加分

`getShareCode` 返回的 `shareCode` 实际按账号（可能+当天）固定/缓存，同一账号短时间内重复调用会拿到完全相同的 `shareCode`，与传入的 `article_id`/`risk_request_info` 内容无关。`shareReporting` 接口即使命中"今日已分享过/已达上限"也会返回 `{"code":"success","message":"上报成功"}` 这种误导性的成功响应，并不代表能量体真的增加了。

该任务大概率有"每日分享加分次数上限"（很可能是 1 次/天），已验证过一次完整成功案例（point 19 -> 24，+5），但同一账号当天第二次调用虽然接口显示成功，能量体却没有变化。**调用方需要自行通过对比调用前后 `GET /app/energy/myEnergy` 的 `point` 字段来判断分享是否真正生效，接口返回码本身不可靠。**

## 其他细节

- `sweet_security_info` 中的 `channel` 字段需为 URL-encoded 值（如 `"%E5%90%89%E5%88%A9"` 表示"吉利"），因为 HTTP 头只能是 ASCII 字符。
- `shareReporting` 用 GET 方法会返回 `{"code":"fail","message":"网络开小差，请稍后再试"}`；POST 但不带 `businessNo`/`eventData` 时虽也返回成功但不会真正加分。

## 动态获取最新文章 id（`get_latest_article()`）

`POST /app/explore/home-page/square/index2`（H5 签名）返回探索广场内容流，用于动态取一篇文章的 `articleId`/`title` 代替硬编码，避免固定文章被下架后失效。

已通过真机抓包+实测验证：该接口原生 App 端请求时 body 会带上 `{"dynamicSort":"new","uniqueId":"","refreshType":"MORE","pageNo":<页码>}` 分页参数。H5 签名算法（`build_signature`）只对 query 参数签名、不覆盖 body，因此把这些参数直接放进 H5 请求的 body 同样能被服务端接受（返回 `success`），且效果验证如下：

- **不带这些参数**（即 body 为 `{}`）时，接口只返回首屏内容，命中"文章"类型内容的概率很低（实测约 1 篇/页，经常被视频/图文动态淹没）；
- **带上这些参数**后，单页可命中 7~11 篇文章，且 `pageNo=1`/`pageNo=2` 返回的文章完全不重复，属于真实分页而非随机推荐流。

`get_latest_article()` 依次翻 `EXPLORE_SQUARE_PAGE_COUNT`（默认 2）页，把所有页命中的"文章"类型内容去重汇总后随机挑一篇返回，而不是命中第一个就返回，进一步提高取到文章的成功率、避免每次都固定分享同一篇。`do_share()` 调用失败/未取到候选时会自动回退到 `DEFAULT_SHARE_ARTICLE_ID`（此时无标题）。分享成功时 `do_share()` 返回值中会带上 `articleId`/`articleTitle`，供 `lynkco_notify.py` 推送文案展示分享的文章标题。
