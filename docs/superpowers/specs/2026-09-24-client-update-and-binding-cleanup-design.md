# 客户端更新能力与绑定流程收敛设计

日期：2026-09-24

本设计整合当前已确认的客户端更新需求，以及 `TODO.md` 中尚未实现的绑定流程、运行记录、分享能力、代理退出和登录态请求策略。此前的《绑定流程与任务控制设计》作为运行记录和第三步交互的背景说明，本文件给出最终收敛后的实现边界。

## 目标

- 首次打开客户端时展示免费使用和防诈骗提示。
- 增加统一版本标识、GitHub 作者信息和可点击项目链接。
- 启动时后台检查 GitHub Releases；用户确认后下载、校验并重启更新。
- 绑定流程只保留三步，第三步一次保存任务设置和推送设置，成功后直接进入主面板。
- 主面板拆分手动签到和手动分享；定时任务继续同时执行两步。
- 用现有运行记录表达三种触发类型，保留完整历史和重试状态。
- 删除 `binding_candidates` 凭据临时表；正式绑定只在用户确认保存时创建。
- 删除 `bindings.can_share`，绑定能力固定要求可分享；页面不再提供分享开关。
- 退出客户端时强制停止电脑代理，并提示关闭手机 Wi-Fi 代理。
- 在不把 access token 上传或持久化到云端的前提下，当前本地会话优先使用有效 access token；只有缺失、过期或上游明确未授权时才刷新 refresh token。

## 当前约束

- `desktop/launcher.py` 是正式包和本地 Worker 包共用的单一启动入口，原生登录窗口由 `desktop/native_auth.py` 提供。
- Cloud 目前在 `GET /v1/binding` 和 runner 任务中直接调用 `/auth/login/refresh`，数据库只保存加密 refresh token。
- 绑定验证目前使用 `binding_candidates` 表保存加密凭据，激活时再转写到 `bindings`。
- `daily_runs` 目前以 `(binding_id,business_date)` 唯一，无法记录同一天独立的手动签到和手动分享。
- GitHub Actions 已按平台发布 `LynkCoHelper-cloud-{platform}.zip` 和对应 `.sha256` 文件。

## 客户端首次提示、版本和作者

### 首次提示

原生窗口初始化后检查状态目录中的 `first-run-notice-v1` 标记。不存在时显示模态提示：

> 该软件免费，邀请码也免费。  
> 如果你花钱了，那么恭喜你被骗了。

弹窗只有“我知道了”按钮。用户确认后才写入标记；直接关闭客户端不会写入，下次继续提示。该提示不阻塞后台更新检查，也不触碰账号凭据。

### 版本来源

新增单一版本模块，源码运行显示 `开发版`，发布构建由规范化的 `cloud-vX.Y.Z` 标签注入 `X.Y.Z`。PyInstaller 包、原生窗口、网页本地状态和更新比较全部读取同一值，不能在不同文件中重复维护版本号。

### 作者信息

固定显示 `GitHub @shovelshit`，链接为 `https://github.com/shovelshit/LynkCoHelper`。原生窗口底部和网页主面板底部显示版本与作者；点击链接使用系统默认浏览器打开。链接是公开项目地址，不携带账号或本地状态。

## 自动更新

### 检查

客户端启动后在后台请求 GitHub Releases 的 latest 元数据。请求有短超时和一次性失败处理，失败只记录状态，不阻塞登录、抓包和主面板。比较当前版本与 latest `tag_name`；开发版、本地 Worker 版不参与正式更新。

### 提示和下载

发现更高版本时，在原生登录窗口或运行状态页显示当前版本、最新版本和“立即更新 / 稍后”操作。用户选择立即更新后：

1. 按当前平台选择对应 zip 资产和 `.sha256` 资产。
2. 下载到状态目录临时文件，限制响应大小并支持取消。
3. 计算 SHA-256，与发布校验文件的文件名和摘要匹配。
4. 解压到同级临时目录并确认包含预期的应用目录和完整性清单。
5. 启动同包 updater 子进程，传入父进程 PID、当前应用路径、临时应用路径和备份路径。
6. 客户端退出后 updater 原子替换应用目录，失败时恢复备份；成功后重新启动应用。

更新不会静默重启。校验失败、平台资产缺失、磁盘空间不足或替换失败都保留旧版本并显示可理解的错误。更新器不接触登录码、管理 token、refresh token 或手机抓包内容。

### 发布兼容

正式客户端只接受 `LynkCoHelper-cloud-{windows-x64|macos-arm64|macos-intel}.zip`。本地 Worker 构建继续使用回环服务地址和 `-dev` 包名，不会被 latest Release 覆盖。现有发布工作流需要在构建阶段将同一个 release tag 传给版本注入步骤。

## 绑定流程收敛

### 三步流程

1. 连接与配置：启动电脑代理、配对手机和证书。
2. 抓包并验证：采集登录、设备和分享上下文，显示验证状态。
3. 保存到云端：账号预览、任务区间、推送配置一起提交。

去掉第四步、保存完成页和单独断开页面。保存成功后直接跳转主面板；退出客户端时由原生关闭路径负责停止代理并提示手机端处理。

### 去掉 `binding_candidates`

`POST /v1/binding-candidates` 改为无持久化的预览校验接口，保留旧路径一段兼容期但不再写入候选表。接口只返回验证后的公开预览、能力状态和短期过期时间，不返回 refresh token，也不写入数据库。

桌面 Controller 在本机内存保存当前抓包会话和预览；浏览器 `sessionStorage` 只保存非敏感的流程 nonce、过期时间和预览字段，不保存 refresh token 或 access token。用户点击第三步保存时，桌面端通过本地受保护 API 将内存中的 refresh-only 会话和配置一次提交到新的绑定保存逻辑；Cloud 在该请求中验证、刷新、读取个人信息并直接创建/替换 `bindings`。

激活失败时本机保留捕获会话和表单，允许重试；成功后清理本机临时会话。`users` 表在领取邀请码时已经落记录，管理员看板通过 `users LEFT JOIN bindings` 显示“已领取未绑定”，不再需要凭据候选表。

### 保存请求

绑定保存请求包含：账号标签、执行区间、refresh-only 会话、分享上下文和通知配置。`doShare` 不再由客户端控制，服务端固定为 true。通知配置在同一绑定事务中加密写入；`不推送` 是有效配置。事务提交后再发送通知测试，测试失败不回滚绑定。

## 分享能力

删除 `bindings.can_share` 和候选表中的 `can_share`。激活和替换绑定时必须通过完整分享上下文校验；缺少上下文直接返回 `CAPTURE_INCOMPLETE` 或 `SHARE_UNAVAILABLE`。页面移除分享开关和相关提示，主面板只展示固定的每日分享状态。

迁移期间保留 `do_share` 列以读取旧记录，但所有新写入和定时运行都固定为 1；待兼容期结束后再删除该列。历史运行记录保留原结果，不重放分享。

## 运行记录与手动任务

### 数据模型

`daily_runs` 增加 `run_type`：

- `scheduled`：定时组合任务，执行签到和分享。
- `manual_sign`：只执行签到。
- `manual_share`：只执行分享。

迁移重建表并移除原有 `(binding_id,business_date)` 表级唯一约束，增加部分唯一索引，仅保证每个绑定每天最多一条 `scheduled` 记录。手动记录每次点击都新建一条，允许同一天重试和保留审计历史。旧记录默认标记为 `scheduled`。

手动签到记录的 `share_status` 固定为 `skipped`；手动分享记录的 `sign_status` 固定为 `skipped`。现有租约、凭证版本、重试次数、未知结果和通知状态继续沿用。

### API

`POST /v1/binding/runs` 接受 `{ "runType": "manual_sign" }` 或 `{ "runType": "manual_share" }`。缺少 `runType` 的旧客户端继续按 `scheduled` 兼容。桌面本地 `/api/binding/run` 增加同名参数，主面板两个按钮显式传不同类型。

定时 runner 按 `scheduled` 同时执行签到和分享；手动 runner 不调用另一项。没有推送渠道时 `notification_status=skipped`，不能把任务标记为失败。

## access token 优先策略

access token 只存在桌面进程内存和当前浏览器 `sessionStorage` 的一次性短期缓存，禁止写入 Cloud 数据库、日志、更新包或普通业务响应。需要 Cloud 代为读取上游资料时，桌面端只通过受保护的短暂请求传递 access token；Cloud 使用后立即丢弃，不写入数据库、队列、缓存或日志。每个 token 绑定 capture id、access revision 和过期时间，捕获会话变化或过期立即清除。

本地会话仍有有效 access token 时，桌面端的即时资料查询和绑定验证优先使用它；只有上游返回 401/明确 token 失效、access token 缺失或超过本地过期时间，才调用 refresh 接口并更新内存中的 refresh token。云端定时任务没有可用 access token 时继续使用加密 refresh token，这是重启、后台运行和手机会话不在本机时的必要回退。

为避免页面刷新重复触发 refresh，桌面 Controller 缓存最近一次已验证的 binding/inventory 快照和其访问令牌状态；短时间内页面只读取本地缓存，过期或收到明确未授权后再向 Cloud 请求刷新。Cloud 只接受桌面本地受保护接口转发的 access token，不接受网页直接提交的 token，也不因页面加载直接强制刷新凭据。

## 退出和代理

所有关闭路径统一先调用 `ProxyManager.stop()`，不要求用户先勾选页面复选框。电脑代理停止后显示：

> 电脑代理已关闭，请在手机 Wi-Fi 设置中关闭代理，否则可能导致网络异常。

用户确认提示后继续退出。若代理已经停止，避免重复停止，但检测到手机代理仍可能活动时仍显示提醒。

## 测试与迁移顺序

- Desktop：首次提示只出现一次、版本/作者展示、更新元数据解析、摘要校验、更新器替换失败回滚、退出强制停代理、access token 缓存和过期回退。
- Cloud：无候选表预览和激活、用户与绑定的关联及管理员视图、分享能力强制校验、运行记录迁移和三种 `run_type`、通知原子保存、旧客户端兼容。
- UI：第三步一次提交、两个手动按钮传递不同类型、无推送可保存、版本作者链接可见、更新失败不阻塞登录。
- 回归：现有桌面全量测试、Cloud 全量测试、打包 smoke test 和三平台资源完整性校验。

迁移顺序为：先发布兼容数据库和 runner，再发布无候选表 API 与手动运行 API，然后发布桌面三步流程和更新器，最后清理 `can_share`、`do_share` 兼容分支及旧 UI 残留。
